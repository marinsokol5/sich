# Example: the Quickstart, step by step

This is the README's Quickstart run for real, with every command's output and
every file sich generates. It was generated by
[`scripts/make-example.sh`](../scripts/make-example.sh) (`pnpm run docs:example`).

The only difference: instead of `--gh` creating private GitHub repos, the layers
get local remotes. `~/remotes/` stands in for GitHub: `myproject.git` is the
public repo, `myproject-personal.git` and `myproject-team.git` are the private
ones.

`~/myproject` starts as an ordinary repo with `README.md` and `src/app.js`,
pushed to its public remote. It also has a few files that shouldn't be public:
`my-notes.md`, `roadmap.md`, `api-keys.env` and `llm-transcripts/`.

## 1. A personal layer, just for you

```console
$ sich init

installed pre-commit hook -> .git/hooks/pre-commit
installed pre-merge-commit hook -> .git/hooks/pre-merge-commit
initialized sich in ~/myproject
$ sich new personal --remote ~/remotes/myproject-personal.git
created layer personal: git data -> .sich/personal/, claims list -> .sich/personal.paths
set origin of personal -> ~/remotes/myproject-personal.git
installed pre-commit hook of personal -> .sich/personal/hooks/pre-commit
installed pre-merge-commit hook of personal -> .sich/personal/hooks/pre-merge-commit
next: sich claim personal <path>...  then  sich commit personal -m <msg>  and  sich push personal
$ sich claim personal my-notes.md
claimed my-notes.md for personal -> .sich/personal.paths
hidden from base -> .git/info/exclude
staged in personal; commit with: sich commit personal -m <msg>
$ sich personal commit -m "adding notes"

```

```console
$ sich new team --remote ~/remotes/myproject-team.git

set origin of team -> ~/remotes/myproject-team.git

installed pre-merge-commit hook of team -> .sich/team/hooks/pre-merge-commit

$ sich claim team roadmap.md api-keys.env llm-transcripts/

staged in team; commit with: sich commit team -m <msg>
$ sich status -v
```

`sich commit` commits base and every layer with changes at once (here only
`team` has any), and `sich push` pushes them all:

```console
$ sich commit -m "adding team files"

$ sich push
base: git push
Everything up-to-date
personal: git push
Everything up-to-date
team: git push -u origin main
To ~/remotes/myproject-team.git
 * [new branch]      main -> main
branch 'main' set up to track 'origin/main'.
```

## 3. What each repo sees

All files in the folder (git data folders collapsed):

```text
.git/
.sich/
.sich/personal/
.sich/personal.paths
.sich/team/
.sich/team.paths
README.md
api-keys.env
llm-transcripts/
llm-transcripts/2026-01-01-planning.md
my-notes.md
roadmap.md
src/
src/app.js
```

Plain `git` only sees base files, and the public remote never learns the private file names:

```console
$ git status
On branch main
Your branch is up to date with 'origin/main'.

nothing to commit, working tree clean
$ git ls-files
README.md
src/app.js
$ git -C ~/remotes/myproject.git ls-tree -r --name-only main
README.md
src/app.js
```

Each layer tracks only its own claims plus its claims list:

```console
$ sich personal ls-files
.sich/personal.paths
my-notes.md
$ sich team ls-files
.sich/team.paths
api-keys.env
llm-transcripts/2026-01-01-planning.md
roadmap.md
$ sich which api-keys.env
team
```

## 4. The files sich generates

Claims lists, tracked by their own layer so collaborators get them:

`.sich/personal.paths`

```text
# Paths owned by sich layer 'personal': one root-relative path per line, directories end with /
my-notes.md
```

`.sich/team.paths`

```text
# Paths owned by sich layer 'team': one root-relative path per line, directories end with /
api-keys.env
llm-transcripts/
roadmap.md
```

Base hides `.sich/` and every claim. This file lives in `.git/` and is never pushed:

`.git/info/exclude` (sich block)

```text
# >>> sich: managed, do not edit >>>
/.sich/
/api-keys.env
/llm-transcripts/
/my-notes.md
/roadmap.md
# <<< sich <<<
```

Each layer ignores everything except its own claims:

`.sich/personal/info/exclude` (sich block)

```text
# >>> sich: managed, do not edit >>>
/*
!/.sich/
/.sich/*
!/.sich/personal.paths
!/my-notes.md
/api-keys.env
/llm-transcripts/
/roadmap.md
# <<< sich <<<
```

`.sich/team/info/exclude` (sich block)

```text
# >>> sich: managed, do not edit >>>
/*
!/.sich/
/.sich/*
!/.sich/team.paths
!/api-keys.env
!/llm-transcripts/
!/roadmap.md
/my-notes.md
# <<< sich <<<
```

The pre-commit hooks that guard base and each layer:

`.git/hooks/pre-commit`

```text
#!/bin/sh
# Installed by sich: stop private (layer-claimed) files from being committed to base.
sich="${SICH_BIN:-sich}"
if ! command -v "$sich" >/dev/null 2>&1; then
  echo "sich: commit blocked: '$sich' not found; put sich on PATH or set SICH_BIN (skip once: git commit --no-verify)" >&2
  exit 1
fi
exec "$sich" check --staged
```

`.sich/personal/hooks/pre-commit`

```text
#!/bin/sh
# Installed by sich for layer personal: stop files personal doesn't own from being committed to it.
sich="${SICH_BIN:-sich}"
if ! command -v "$sich" >/dev/null 2>&1; then
  echo "sich: commit blocked: '$sich' not found; put sich on PATH or set SICH_BIN (skip once: sich personal commit --no-verify)" >&2
  exit 1
fi
exec "$sich" check --staged
```

Each repo also gets a `pre-merge-commit` hook, which git runs instead of
`pre-commit` for a merge commit made without conflicts. It differs only in its
messages and in passing `--merge`, so a blocked merge says how to back out:

```console
$ diff .git/hooks/pre-commit .git/hooks/pre-merge-commit
5c5
<   echo "sich: commit blocked: '$sich' not found; put sich on PATH or set SICH_BIN (skip once: git commit --no-verify)" >&2
---
>   echo "sich: merge blocked: '$sich' not found; put sich on PATH or set SICH_BIN (skip once: git merge --no-verify)" >&2
8c8
< exec "$sich" check --staged
---
> exec "$sich" check --staged --merge
```

## 5. The guard in action

Forcing a private file into base gets blocked:

```console
$ git add -f my-notes.md
$ git commit -m "oops"
✗ base has a staged change to private path my-notes.md (claimed by personal)
  unstage with: git restore --staged -- my-notes.md
sich check: 1 issue found
$ git restore --staged my-notes.md
```

So does forcing a file into a layer that hasn't claimed it (`sich personal add`
is plain `git add`; `sich claim` is what claims files):

```console
$ echo "draft" > draft.md
$ sich personal add -f draft.md
$ sich personal commit -m "draft"
✗ personal has a staged change to draft.md, which none of its claims cover
  claim with: sich claim personal draft.md
  or untrack with: sich personal rm --cached -- draft.md
sich check: 1 issue found
$ sich personal rm -q --cached -- draft.md
```

## 6. A collaborator joins

A collaborator with access to `myproject-team` (but not `myproject-personal`)
clones base and attaches the `team` layer:

```console
$ git clone -q ~/remotes/myproject.git && cd myproject
$ sich attach team ~/remotes/myproject-team.git
created .sich/ (holds every layer's git data and claims list)
excluded .sich/ from base -> .git/info/exclude
installed pre-commit hook -> .git/hooks/pre-commit
installed pre-merge-commit hook -> .git/hooks/pre-merge-commit
attached layer team from ~/remotes/myproject-team.git -> .sich/team/ (branch main)
checked out 4 files: .sich/team.paths, api-keys.env, llm-transcripts/2026-01-01-planning.md, roadmap.md
installed pre-commit hook of team -> .sich/team/hooks/pre-commit
installed pre-merge-commit hook of team -> .sich/team/hooks/pre-merge-commit
$ ls -A
.git
.sich
README.md
api-keys.env
llm-transcripts
roadmap.md
src
$ sich status
base  main  origin/main up to date  clean
team  main  origin/main up to date  clean
```

They get `roadmap.md`, `api-keys.env` and `llm-transcripts/`, but `my-notes.md`
never reaches them, and nothing tells them a `personal` layer exists.
