# Example: one project, two private layers

This walkthrough was generated by [`scripts/make-example.sh`](../scripts/make-example.sh)
(`pnpm run docs:example`), so every command and output below is real. `~/remotes/`
stands in for GitHub: `myproject.git` is the public repo, `myproject-notes.git`
and `myproject-keys.git` are private ones (with `--gh`, sich would create those
on GitHub instead).

`~/myproject` starts as an ordinary repo with `README.md` and `src/app.js`,
pushed to its public remote.

## 1. Set up two layers

`notes` is just for you; `keys` is shared with your team.

```console
$ sich init
created .sich/ (holds every layer's git data and claims list)
excluded .sich/ from base -> .git/info/exclude
installed pre-commit hook -> .git/hooks/pre-commit
initialized sich in ~/myproject
$ sich new notes --remote ~/remotes/myproject-notes.git
created layer notes: git data -> .sich/notes/, claims list -> .sich/notes.paths
set origin of notes -> ~/remotes/myproject-notes.git
next: sich add notes <path>...  then  sich commit notes -m <msg>  and  sich push notes
$ sich new keys --remote ~/remotes/myproject-keys.git
created layer keys: git data -> .sich/keys/, claims list -> .sich/keys.paths
set origin of keys -> ~/remotes/myproject-keys.git
next: sich add keys <path>...  then  sich commit keys -m <msg>  and  sich push keys
```

Write `NOTES.md`, `roadmap/q1.md` and `.env`, and edit `src/app.js`, then:


## 3. Commit and push everything

`sich commit` commits base and every layer with changes; `sich push` pushes them all.


Plain `git` only sees base files, and the public remote never learns the private file names:

```console
$ git status
On branch main

$ git ls-files
README.md
src/app.js
$ git -C ~/remotes/myproject.git ls-tree -r --name-only main

```

Each layer tracks only its own claims plus its claims list:

```console
$ sich notes ls-files
.sich/notes.paths
NOTES.md
roadmap/q1.md
$ sich keys ls-files
.env
.sich/keys.paths
$ sich which .env
keys
```

## 5. The files sich generates

Claims lists, tracked by their own layer so collaborators get them:

`.sich/notes.paths`

```text
# Paths owned by sich layer 'notes': one root-relative path per line, directories end with /
NOTES.md
roadmap/
```

`.sich/keys.paths`

```text
# Paths owned by sich layer 'keys': one root-relative path per line, directories end with /
.env
```

Base hides `.sich/` and every claim. This file lives in `.git/` and is never pushed:

`.git/info/exclude` (sich block)

```text
# >>> sich: managed, do not edit >>>
/.sich/
/.env
/NOTES.md
/roadmap/
# <<< sich <<<
```

Each layer ignores everything except its own claims:

`.sich/notes/info/exclude` (sich block)

```text
# >>> sich: managed, do not edit >>>
/*
!/.sich/
/.sich/*
!/.sich/notes.paths
!/NOTES.md
!/roadmap/
/.env
# <<< sich <<<
```

`.sich/keys/info/exclude` (sich block)

```text
# >>> sich: managed, do not edit >>>
/*
!/.env
!/.sich/
/.sich/*
!/.sich/keys.paths
/NOTES.md
/roadmap/
# <<< sich <<<
```

The pre-commit hook that guards base:

`.git/hooks/pre-commit`

```text
#!/bin/sh
# Installed by sich: stop private (layer-claimed) files from being committed to base.
sich="${SICH_BIN:-sich}"
if ! command -v "$sich" >/dev/null 2>&1; then
  echo "sich: commit blocked: '$sich' not found; put sich on PATH or set SICH_BIN (skip once: git commit --no-verify)" >&2
  exit 1
fi
exec "$sich" check --staged
```

## 6. The guard in action

Forcing a private file into base gets blocked:

```console
$ git add -f NOTES.md
$ git commit -m "oops"
✗ base has a staged change to private path NOTES.md (claimed by notes)
  unstage with: git restore --staged -- NOTES.md
sich check: 1 issue found
$ git restore --staged NOTES.md
```

## 7. A teammate joins

A teammate with access to `myproject-keys` (but not `myproject-notes`) clones base and attaches the `keys` layer:

```console
$ git clone -q ~/remotes/myproject.git && cd myproject
$ sich attach keys ~/remotes/myproject-keys.git
created .sich/ (holds every layer's git data and claims list)
excluded .sich/ from base -> .git/info/exclude
installed pre-commit hook -> .git/hooks/pre-commit
attached layer keys from ~/remotes/myproject-keys.git -> .sich/keys/ (branch main)
checked out 2 files: .env, .sich/keys.paths
$ ls -A
.env
.git
.sich
README.md
src
$ sich status
base  main  origin/main up to date  clean
keys  main  origin/main up to date  clean
```

They get `.env`, but `NOTES.md` and `roadmap/` never reach them, and nothing
tells them a `notes` layer exists.
